# 非 TabBar 页面优化实施说明

日期：2026-08-20

## 本轮范围

本轮按 `inviteMaster-non-tab-ui-reference-v1` 的方向，处理模板预览、收到邀请、邀请编辑、我的资料和回复邀请五类非 TabBar 体验，并补齐与这些页面直接相关的路由恢复、异常状态和验证门禁。未改动后端接口，也未上传或发布小程序。

## 已完成

### 1. 收到邀请

- 将页面状态显式拆分为 `loading / ready / invalid / error`。
- 无效分享参数不再无限加载；网络或接口失败提供重新加载和返回首页入口。
- 邀请主体成功后，模板、收藏和回复状态独立加载，单个附属请求失败不会拖垮主页面。
- 音频在重试和页面卸载时销毁，避免重复实例和后台残留。
- 回复面板补充 RSVP 层级，并统一空态、按钮和内容节奏。

### 2. 模板预览与编辑器

- 预览页支持 `templateId`、`invitationId` 查询参数恢复，不再只依赖上一页 `EventChannel`。
- 首页和“我的”中的跳转链接携带稳定业务 ID；编辑页也支持刷新或直达后按 ID 重新加载。
- 预览页和编辑页补充加载失败、重试与返回入口。
- 将模板数据解码、样式更新、业务字段命名和序列化抽到 `templateCodec.ts`，降低编辑页继续扩张的风险。
- 为模板编解码新增 4 个 Node 单元测试，覆盖非法数据、样式替换、vw 序列化和冒号值保留。

### 3. 我的资料

- 将头像与姓名提升为身份卡，资料列表只保留适合逐项编辑的字段。
- 手机号默认脱敏显示。
- 增加隐私说明，明确资料用途和可修改性。

### 4. 回复邀请

- 增加 RSVP 引导、字段说明和祝福语字数反馈。
- 提交期间锁定按钮状态，避免重复提交。
- 清理该流程中的调试日志，并保证 loading 在成功或失败后均被关闭。

### 5. 工程门禁

- 扩大 `tsconfig.verify.json` 的覆盖范围，纳入本轮页面、store、回复表单和模板编解码。
- `npm run verify` 现在依次执行类型检查、单元测试和 `git diff --check`。
- sitemap 仅允许首页被索引，邀请、资料和编辑页面默认不进入搜索索引。
- 当前界面只提供浅色设计，因此移除未落地的深色主题声明，避免系统深色模式出现半套样式。

## 验证边界

- 已验证：扩展后的 TypeScript 检查、4 个模板编解码测试、diff 空白检查、生产依赖安全审计、微信开发者工具登录与 `build-npm`/项目打开。
- `build-npm` 的“没有 npm 构建产物”提示符合项目当前无小程序 npm 依赖的状态，不是构建失败。
- 开发者工具本轮自动重载未出现 WXML、WXSS 或 JavaScript 语法错误；已移除自定义 TabBar 下多余的 `wx.hideTabBar` 调用。日志中偶发动态字体下载超时，现有字体栈会回退到系统字体。
- 尚需真机确认：Skyline 下的长内容滚动、音频后台行为、位置授权、回复弹层键盘顶起、不同机型安全区和分享落地页。

## 仍需后续处理

1. 分享链接目前仍使用可枚举的邀请数字 ID。若要防止未授权访问，需要后端提供不可猜测、可失效的 `shareToken`，前端再切换到 token 查验。
2. `create.ts` 仍接近千行。本轮只先抽离纯函数；后续可继续拆成画布状态、素材选择、表单编辑和保存发布四个模块。
3. 仓库完整 `tsconfig.json` 仍包含历史 Skyline worklet、WebAudio 和未使用参数等类型问题。本轮门禁覆盖了改动链路，但不能等同于全仓零类型错误。
4. 本轮未执行上传、预览发布或线上接口验收；这些动作需要在明确版本和发布窗口后单独进行。
