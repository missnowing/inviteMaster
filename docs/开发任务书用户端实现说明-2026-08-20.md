# 开发任务书用户端实现说明

更新日期：2026-08-20

## 范围

- 本轮只处理微信小程序用户端。
- 后台管理系统已由独立项目实现，不在本项目范围内。
- 接口依据：`https://witknow.com/witinvite/v2/api-docs` 当前 OpenAPI 契约。

## 已实现

- 首页：沿用已确认的宋式雅致方案，支持关键词搜索、“全部”及主分类切换、今日精选大卡、新作双列陈列和分页加载。
- 导航：调整为“首页、我的、应邀”。
- 收藏：模板收藏和请柬收藏均使用服务端接口，并在“我的”中分开展示。
- 创作：支持保存草稿、发布邀请；已发布作品修改时保持发布状态。
- 回复：遵循匿名、手机号、可修改人数、最大人数等邀请权限；席位信息只读展示。
- 收件页：恢复模板图层渲染，展示邀请词、日期、农历、时间、地点、地图导航、音乐、回复、收藏和转发。
- 我的应邀：按近期/历史分类，加载对应邀请详情并可回到完整请柬。
- 请求层：OpenAPI 中定义为 query 的参数统一放入 URL，JSON 请求体保持 JSON 传输。
- 工程配置：基础库统一到 `3.16.2`，与当前 Skyline/glass-easel 配置一致。

## 当前后端契约缺口

以下任务书功能在当前 OpenAPI 中没有用户端接口，因此本轮没有伪造地址或写入仅本机有效的数据：

- 邀请方宾客名单、回复统计明细。
- 签到核销、签到记录和二维码签到。
- 席位/桌号分配及调整。
- 礼品、礼金和赠送记录。
- 抽奖配置、参与和开奖记录。
- 活动相册、照片上传/下载、照片评论。
- 活动留言、留言审核和消息通知。
- 工作人员角色、协作权限和邀请。
- 不可枚举的分享令牌；现有分享仍使用邀请函数字 ID。

建议后端按邀请函维度补充独立资源接口，并在 OpenAPI 中明确分页结构、权限、状态枚举和错误码后再继续接入。

## 验收边界

- 已通过 TypeScript 静态校验和 `git diff --check`。
- 已在微信开发者工具中触发 Skyline 编译并正常进入首页、完成首页接口请求。
- 收藏写入、草稿/发布、回复修改、地图和转发仍需使用真实微信账号与业务数据做真机验收。
